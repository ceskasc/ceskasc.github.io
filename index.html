About

Engineering that feels considered.

The best software feels obvious to use and boring to maintain — in the best possible way.

I work across front-end interfaces, backend services, APIs, and product architecture. I care about the decisions between those layers just as much as the code inside them.

My preference is simple: fewer fragile abstractions, stronger fundamentals, and enough visual restraint that the product itself stays in focus.

01

Interface systems

Responsive UI, component architecture, accessibility, interaction and visual consistency.

02

Application systems

APIs, data flows, authentication, integration boundaries and maintainable backend logic.

03

Product delivery

Scoping, trade-offs, implementation choices and shipping with a clear quality bar.

Working principles

Quality is a system, not a finishing touch.

01

Make the structure legible.

Clear data flow, state ownership, naming, and component boundaries make products easier to extend and safer to change.

02

Treat details as product behavior.

Typography, loading states, empty states, keyboard access, responsive layouts, and performance all affect trust.

03

Prefer durable over clever.

I choose solutions that remain understandable after the initial excitement of shipping has passed.
