03About

A bias for clarity.
A taste for detail.

I like software that feels obvious to use and surprisingly uneventful to maintain.

That means fewer fragile abstractions, deliberate boundaries, thoughtful defaults, useful loading and empty states, keyboard access, responsive behavior, and performance treated as part of the experience — not cleanup after the fact.

I care about the decisions between layers as much as the code inside them.

01
Make structure legible.

Readable systems are faster to extend, debug, and trust.

02
Design behavior, not decoration.

States, timing, hierarchy, and feedback are product decisions.

03
Prefer durable over clever.

The best solution should still make sense after the excitement is gone.
